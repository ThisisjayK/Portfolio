# Portfolio

Source for my product-management portfolio: **[thisisjayk.github.io/Portfolio](https://thisisjayk.github.io/Portfolio/)**

I'm an early-career PM (MS Information Systems, Northeastern, 2026). The site holds
case studies, a product teardown, and the reasoning behind each claim rather than a
list of adjectives.

## What's on it

| Page | What it is |
|---|---|
| `/` | Single-page site: experience, skills, and the way I work |
| `/case-studies/stage-zero-health` | "Screening the Women the Guidelines Miss" — five months as a technical PM intern at Stage Zero Health, a pre-seed early cancer detection company. I owned the Breast Cancer Journey from onboarding to a booked screening. Problem → Solution → Impact, with an `EVIDENCE.md` alongside it. |
| Kick teardown | "Improving Discovery of Kick" (Easygo Entertainment). Outside-in analysis with no internal data: a timed cold-start task, then adversarial testing of two proposed controls. I note up front that I'm a daily Kick viewer, which cuts both ways. |

The rule I hold the content to, quoted from `src/data/skill-evidence.ts`:

> A skill only appears here if there is a real story behind it in something
> published on this site. Everything else stays off the list.

Same idea in the site's own description: run the task first, tie every claim to
evidence, name the counter-metric up front.

## Stack

React + TypeScript on Vite. Three.js via `@react-three/fiber` and `@react-three/drei`,
plus `ogl`, `gsap`, `motion`, and `gl-matrix` for the animated pieces. Sprite sheets
for the mascots are generated by the Python scripts in `scripts/`.

```bash
npm ci
npm run dev      # local dev server
npm run build    # production build into dist/
```

Deployed by GitHub Actions (`.github/workflows/deploy.yml`) to GitHub Pages on every
push to `main`.

## Two implementation notes

**The résumé is LaTeX, and the copy the site serves is generated.** `resume/resume.tex`
is the source; `resume/resume.pdf` is the one tracked build. `scripts/sync-assets.mjs`
runs on `predev` and `prebuild` and copies it to `public/jayanth-resume.pdf`, which is
the filename every link on the site points at. Before that script existed, editing
`resume.tex` and forgetting to re-copy shipped a stale résumé while every link kept
working, which is the worst kind of bug: silent and user-visible.

**`src/data/` is deliberately separate from components.** Experience, skills,
brand logos, and volunteer entries are plain data files, so updating content doesn't
mean touching JSX.

## On how it was built

Written with heavy AI assistance (Claude Code). I'm a PM, not a frontend engineer,
and I don't write TypeScript unaided. The decisions I own are what goes on the site,
what order it goes in, and what evidence each claim rests on. The implementation was
a means to publish those.
